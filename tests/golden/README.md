# tests/golden — differential harness against the Python engine

Ivory 2.0 (the Rust `ivory-core` engine) is validated against the *shipped*
Python `ChordDetector` by diffing both over a large corpus of note-sets and
classifying every divergence to a documented rule in
[`docs/DIVERGENCES.md`](../../docs/DIVERGENCES.md). This directory holds the
corpus, the frozen engine baseline, the classification, and the audit.

## Files

| file | what it is |
|---|---|
| `corpus.json` | 13,133 note-sets with the Python engine's output: `{notes, src, flat, sharp}`. `src` tags origin: `pattern:<chord>:<voicing>`, `random`, `interval:<n>`, `scale:<name>`, `edge:*`, `single`. Generated by `gen_corpus.py`. |
| `gen_corpus.py` | regenerates `corpus.json` from the reference Python engine (`chord_detector.py`). Requires that engine on disk. |
| `rust-golden.json` | **the frozen regression baseline** — the current engine's `detect_chord` output `{notes, flat, sharp}` for all 13,133 note-sets, both naming preferences. |
| `classify.py` | classifier: reads `corpus.json` + `rust-golden.json`, maps every mismatch to a D/K-rule id, writes `classified-divergences.json`, prints per-rule counts. Self-contained (embeds the name→pitch-class reconstructor and chord table). |
| `classified-divergences.json` | one record per mismatching row: `{notes, src, python_flat, rust_flat, python_sharp, rust_sharp, rule}`. Covers both flat and sharp renderings (every rule is pitch-class-relational). |
| `UNEXPLAINED.md` | hand-audit of the 365 rows no heuristic ties to a rule: family verdicts, the 28-row regression-concern shortlist, and a cross-rule "rust-correct / Python-buggy" confirmation table. |

The engine-side self-consistency guard lives in
[`ivory-core/tests/differential.rs`](../../ivory-core/tests/differential.rs).

## Divergence summary

5,195 of 13,133 rows differ (identical count for flat and sharp — every
divergence is pitch-class-relational). Per-rule breakdown from `classify.py`:

| rule | rows | what it corrects |
|---|---|---|
| D2-scoring-better | 1407 | pure scoring (no state leak); rust names a tighter chord |
| D9-rootless-dom | 521 | rootless dominant → implied real root via the tritone |
| D2-scoring-equal | 537 | pure scoring; rust equal-fit, different spelling |
| D17-scale | 497 | ≥8 unique PCs → scale, not a chord |
| D4-lydian-demote | 416 | Python's spurious `Δ7(#11)` lydian reading → dominant |
| D17-none | 379 | ≥8 unique PCs, no scale hit → `None` |
| D4-altdom-bass | 321 | altered dominant named from the bass root |
| D3-tertian-bass | 254 | 6/7-PC tertian stack named from the bass root |
| D20-m11-vs-sus69 | 167 | root≠bass m11 bonus gated; sus/6-9/7sus wins |
| D19-inversion-9th | 136 | keep the 9th/13th instead of a dead `X7/bass` inversion |
| D3D4-bass-coherent | 68 | general bass-coherent rename |
| D6-b9-parens | 42 | bare `7b9` → `7(b9)` |
| D10-dom9-inversion | 33 | dominant-9 inversion → complete `X9/bass` |
| D1-m7-not-rel6 | 25 | closed complete m7 named from its root, not relative 6 |
| D8-13sus | 22 | b7 present ⇒ 13sus over 6/9-no3 |
| AUDIT-* (see UNEXPLAINED.md) | 365 | no rule; hand-audited |
| D5-dim-slash-7b9 | 4 | dim slash → root-position `7(b9)` |
| D12-dim-m6 | 1 | diminished-triad set spelled as bass-coherent m6 |

`AUDIT-*` split: `ambiguous-dense` 210, `ambiguous-voicing` 81,
`rootless-shell-voicing` 36, `chromatic-cluster` 23, `aug-symmetry` 15.

**Rust-correct / Python-buggy:** 2,149 rows where rust is a strictly tighter
description than Python, plus the D-rule fixes above (D1/D3/D4/D5/D6/D8/D9/
D10/D12/D17/D19/D20) — Python's over-naming (`Δ7(#11)` 5,570× in its own
output), relative-6 flips, dim slashes, dead inversion names, and reduction
lottery are all corrected. Pattern-generated rows (`pattern:X:voicing`) whose
rust output names chord `X` where Python did not are rust being correct.

**Suspected real regressions:** 28 rows in two families (`major7#5` drop-2 and
`major7#11` drop-2), where a simpler name edges out the complete one and drops
a sounded tension — both boundary effects of the intended `Δ7(#11)` demotion.
Ranked and detailed in `UNEXPLAINED.md`. No broad-scoring change was found to
mislabel a clean, complete, common chord Python got right.

## Regenerate

```sh
# 1. Python corpus (needs the reference chord_detector.py on disk)
python3 tests/golden/gen_corpus.py tests/golden/corpus.json

# 2. Rust baseline + live mismatch counts
cargo run -p ivory-core --example diffcorpus --release -- \
    --json tests/golden/rust-golden.json
cargo run -p ivory-core --example diffcorpus --release -- --dump   # list mismatches

# 3. Re-classify
python3 tests/golden/classify.py

# 4. Self-consistency guard
cargo test -p ivory-core --test differential                 # fast subset (default)
cargo test -p ivory-core --test differential -- --ignored    # full 13,133-row sweep
```

## Audit method

1. Reconstruct each name (Python's and rust's) to a pitch-class set via the
   chord table in `classify.py`; score `error = missing + extra` against the
   sounding notes.
2. Rows where rust fits equal-or-better are accepted (they *are* the fixes).
3. Rows where rust fits worse are family-bucketed; the fit metric is treated as
   advisory only — it over-penalises legitimate extension shorthand
   (`Cm13` = C-Eb-A-Bb).
4. Every worse-fit family, and the specific "rust dropped a sounded note"
   candidates, were re-checked against the live engine
   (`ChordDetector::detect_chord_debug`, candidate scores) before a verdict.
5. `differential.rs` freezes the audited output: any future engine change that
   moves a single row turns it red, forcing a deliberate baseline regeneration.
